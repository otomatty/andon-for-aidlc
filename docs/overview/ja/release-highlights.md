## 2.11.2 で変わったこと

[2.11.2](releases/2.11.2.md) は2026年10月28日公開です。State Version 8 と基本 33 ステージは維持します。

| 変更 | 利用時の動作 |
| --- | --- |
| 本人の言葉と返答の記録 | どの質問でも、どのチャットからでも、返答を本人の言葉のまま選択肢と照らして読みます。記録には、各決定のもとになった返答がそのまま残ります。チャットに入力したキーやパスワードは、コミットされる記録では `[masked]` に置き換わります |
| 学びの記録 | 承認前の学びの確認は、そのステージで本人がエージェントを訂正したときだけ尋ねます（`You asked me to <your change>. Keep that for next time?`）。訂正がなければ、要約からそのまま承認か差し戻しに進みます |
| ゲートとレビュー | 先へ進む道のない「<Stage> can't go ahead as things stand」の質問が、Guard Policy strict でも大幅に減りました。承認前のレビュー要約は、Approve でリスクとして受け入れる未解決の指摘を示し、指摘ごとに修正の依頼や理由を添えた却下もできます |
| 計画の切り替えとジャンプ | 計画の切り替え、スキップ、取り消し、ジャンプ、`--single` での単独実行が、今いる場所から続きます。Requirements Analysis と Domain Design のゲートでは、合うステージがスキップされていれば「Approve, and add <Stage> next」を選べます |
| 多数のリポジトリ | 多数のリポジトリがあるワークスペースでも Reverse Engineering がゲートまで届きます。名前を挙げていないリポジトリが 10 以上見つかった場合は、読む前に一度だけ尋ねます。`/aidlc intent add-repo <name>` で、どのステージでもリポジトリを作業に加えられます |
| 並行ビルド | Unit の並行ビルドは本人のブランチから始まって同じブランチに戻り、各 Unit が記録に加えた変更も持ち帰ります |
| 本人のファイル | Code Generation の承認の質問（または各 Unit のチェックポイント）は、作業前からあったファイルのうちビルドが変更・削除したものを、git で元に戻すコマンドとともに示します |
| Build and Test | 毎回必ず作るのは 4 つのファイルで、結合・性能・セキュリティのテスト指示は、それを求めるテスト戦略のときだけ作ります。プロジェクト全体のカバレッジ床は全テストの実行で判定します |
| セットアップと Doctor | ターミナルでの `aidlc config --yes` は何も尋ねません。`aidlc doctor` は古い更新確認がいつのものかを示し、別のクローンで進んだ作業はフックの異常ではなく、そのマシンを示す警告になります |

更新は `aidlc update` の後、各プロジェクトで `aidlc config --yes` を実行します（進行中の作業はそのまま続きます）。手動コピーでは `aidlc-copy-runtime-2.11.2.tar.gz` の `runtime/<harness>/` 全体を置き換えます。スクリプトに影響する変更は 3 つです。ネイティブの `aidlc` もあるマシンで、コピーしたプロジェクト自身の `config` を `--from` なしで実行する場合は `--download` か `--from` が必要になりました。AI-DLC を動かすスクリプトや CI ジョブは `AIDLC_UNATTENDED=1` を設定します。Claude Code では Amazon Bedrock の回答が Git の対象外の `.claude/settings.local.json` に書かれるため、AWS のプロファイルは `harness.json` ではなく `aidlc config providers --show --json` から読みます。

Andon では、プロジェクトやエンジンの版が対応版（2.11.2）と違うと「バージョン確認」の画面を表示し、必要な更新を案内します。

## 2.11.1 で変わったこと

[2.11.1](releases/2.11.1.md) は2026年10月20日公開です。State Version 8 と基本 33 ステージは維持します。

| 変更 | 利用時の動作 |
| --- | --- |
| Code Generation の承認 | worktree（子フォルダー・`.worktrees/`・プロジェクト外のリポジトリ）、clone、サブモジュール、モノレポのパッケージに置いたコードでも承認の質問が開きます。レビューからコードが見えない場所では `AI-DLC found no source changes under <where it looked>` と一度だけ伝え、いつもどおり承認または変更の依頼ができます |
| Guard Policy off と会話の圧縮 | ビルドの途中でチャットが圧縮されても、拒否せずに記録済みのビルドステップのまま続けます |
| ゲートからの後戻り | 開いている Code Generation の承認の質問で前のステージへ戻る・やり直す依頼は、どの Guard Policy でも最初の依頼で通ります（GitHub Copilot は従来どおり一度拒否し、次のステップで実行します） |
| 本人の言葉での一時停止 | 「ちょっと待って」「今日はここまで」と止めた本人を先へ促さず、続けるか休むかも尋ねません。保留時は現在地と、`/aidlc --resume` を含む戻り方を示します |
| プラグインの名前とカタログ | 他の人が作ったプラグインは、作者が付けた名前（`<name>@<catalogue>`）で表示されます。AI-DLC 自身のプラグインは、更新をまたいで同じ場所に残る `aidlc-plugins` カタログを共有し、`/plugin marketplace add` で一度追加すれば済みます |
| Bun なしのプラグイン | ネイティブ導入では、Cursor と Kiro IDE のプラグインが Bun なしでセッション開始時に構成されます。2.11.0 でビルドしたプラグインは、作者がこのリリースで再ビルドし、本人が入れ直すまで Bun が必要です |
| 以前のリリースからの更新 | 2.8.0 から 2.11.0 までのどのリリースのプロジェクトも、構成済みのプラグインを含めて止まらずに更新できます |
| 計画の質問 | 作業を始める前に本人の返答を待ちます。待つ間も、読み取り・スキャン・テストの実行・AI-DLC 自身のコマンドは実行されます |
| Construction の担当 | Unit が二つ以上の計画では、Inception の終わりに一度だけ、誰がビルドするか（Just me / Several teams）を尋ねます |
| ステータスライン | AI-DLC のステータスラインを使うかどうかは本人が選び、一度だけ尋ねます。本人の設定を断りなく置き換えません |
| root と `.env` | `install.sh` と `aidlc uninstall` は、コンテナーや CI 向けに明示的な `--allow-root`（または `AIDLC_ALLOW_ROOT=1`）を受け付けます。プロジェクトの `.env` はエンジンに届かなくなりました |

更新は `aidlc update` の後、各プロジェクトで `aidlc config --yes` を実行します（進行中の作業はそのまま続きます）。手動コピーでは `aidlc-copy-runtime-2.11.1.tar.gz` の `runtime/<harness>/` 全体を置き換えます。Claude Code または Codex で AI-DLC のプラグインを使う場合は、新しいカタログのフォルダーを `/plugin marketplace add <folder>` または `codex plugin marketplace add <folder>` で一度だけ追加します。プラグインをビルド・インストールするスクリプトでは、AI-DLC が同梱しないプラグインの名前が `aidlc-<name>@aidlc-plugins` から `<name>@<catalogue>` に変わりました。

AIDLC Guide では、プロジェクトやエンジンの版が対応版（2.11.1）と違うと「バージョン確認」の画面を表示し、必要な更新を案内します。

## 2.11.0 で変わったこと

[2.11.0](releases/2.11.0.md) は2026年10月8日公開です。State Version 8 と基本 33 ステージは維持します。

| 変更 | 利用時の動作 |
| --- | --- |
| スコープの既定値 | `enterprise` 以外は Guard Policy が off、協働エージェント（collaborators）も off。各ステージは主担当エージェントだけで進みます。`/aidlc --collaborators on` で支援エージェントが戻ります |
| Plan Approval | エンジンが尋ね、承認済みの計画は会話の圧縮や中断の後も再び尋ねません。`express`・`poc` は off、`/aidlc --plan-approval on\|off` で切り替えます |
| 返答の読み取り | どのチャットからでも、本人の言葉どおりに読み取って記録します。新しいセッションの `/aidlc` は再開メニューを出さずに作業を続けます |
| 依頼の即時実行 | `--skip`・`--add`、スコープの変更、チャットで伝えた Construction の設定はその場で実行し、戻し方を一行で示します。完了済みの Unit は完了のまま残ります |
| 構成した計画 | その作業だけに属し、スコープファイルを書きません。残すときはゲートで **Approve and save as scope** を選びます |
| 作業中の config | 進行中の作業があっても `aidlc config` を実行でき、変更内容・戻し方・`Updated. Your open work (<name>) carries on.` を表示します |
| チームのファイル | `.claude/settings.json`・`.codex/config.toml`・`opencode.json`・`.gitignore` は AI-DLC の部分だけを更新します。`.gitignore` のブロックはチームの規則の後に置きます |
| フックの未実行 | フックが一度も動かないツールでは、最初のメッセージで止まり、そのツールで必要な手順を示します |
| Windows の管理者実行 | UAC で昇格した窓の `install.ps1` は拒否ではなく警告して確認します。非対話では `-Yes` がない限り停止します |

既存のインテントは、記録済みの Guard Policy・センサー・学習・要約の確認を保持します。Plan Approval と Collaborators はスコープの新しい既定値に従います。更新は `aidlc update` の後、各プロジェクトで `aidlc config --yes` を実行します（進行中の作業はそのまま続きます）。手動コピーでは `aidlc-copy-runtime-2.11.0.tar.gz` の `runtime/<harness>/` 全体を置き換えます。手動コピーには Bun 1.3.8 以降が必要です。

## 2.10.0 で変わったこと

[2.10.0](releases/2.10.0.md) は2026年9月24日公開です。State Version 8と基本33ステージは維持します。

| 変更 | 利用時の動作 |
| --- | --- |
| Constructionの検証 | 対象となる新規ソロワークフローはUnit順・直列実行。人間が許可したコマンドで検証し、Unitまたはバッチのチェックポイントで承認します。既存ワークフローは記録済みの方針を維持します |
| Guard Policy | Change Controlの後継名称。strict・relaxed・offを選択できます。offでも人間の承認ゲートやUnitの所有権は維持します。旧名称はこの版のみ互換読取りします |
| 複数ハーネス | 設定ファイルが衝突しない組合せを同じプロジェクトで利用できます。AGENTS.mdの共通案内と各ハーネスの設定を分けます |
| プロバイダー | Bedrockを明示的に選ばなければ、現在の設定を維持します |
| 作業の復元 | Boltのブランチ・参照・worktreeをIntent別に分離。保留した試行を元のバイト列で復元し、Doctorから復元手順を確認できます |
| 入力とフック | 改行したTesting Posture、推奨ラベル付きの回答、要約質問、根拠・追跡情報、Windowsパス、ネイティブ実行経路を修正しました |

更新はワークフローの合間に行います。`aidlc update` 後、各プロジェクトで `aidlc config --yes` と `aidlc doctor` を実行します。複数ハーネスでは `aidlc config --harness <name> --yes` をそれぞれ実行してください。手動コピーでは `aidlc-copy-runtime-2.10.0.tar.gz` の `runtime/<harness>/` 全体を置き換えます。

## 2.9.0 で変わったこと

[2.9.0](releases/2.9.0.md) は 2026年9月15日公開です。State Version は **8**、基本グラフは **33 ステージ**を維持します。新規 Classic の実行対象は 18 ステージになりました。

| 変更 | 利用時の動作 |
| --- | --- |
| Classic scope v1 | Inception から Build and Test までを実行。ステージ承認と Plan Approval は維持し、Skeleton とサマリー確認は既定で off。Sensors・Learnings は on |
| インテント設定 | 深さ・テスト・レビュー・Change Control・3 種の手続き設定をまとめて適用。不正な値があれば全体を拒否 |
| アーカイブ | 未完了の仕事を記録・監査ごと保持して一覧から外し、必要なら再開 |
| コミット来歴 | レビュー済み Unit とコミット内容を照合し、変更の有無・証拠の不足・信頼の根拠を報告 |
| 自律実行 | Construction 中に許可・取り消し可能。最初の承認、Unit の Plan Approval、失敗時の判断は人間が行う |
| 導入・モデル設定 | Bun のコピー版をネイティブ版から分離。Kiro はプロバイダー回答不要。balanced の effort は 3 グループとも medium |
| レビュー再試行 | 却下後の通し番号を修正し、誤ったレビュー予算超過を防止 |

進行中の Classic は記録済みのグラフを維持します。従来の 26 ステージが必要な新規作業には `workshop` を使い、Standard のテスト水準が必要なら `--test-strategy standard` を指定してください。

## 2.8.2 で変わったこと

2026年9月10日公開の [2.8.2](releases/2.8.2.md) は、サマリー確認、レビュー指摘表の診断、Unit の状態操作を修正します。[2.8.1](releases/2.8.1.md) のネイティブ導入・フック修正も含みます。State Version は 8、基本ステージ数は 33 のままです。

| 版 | 改善前の問題 | 改善後の動作 |
| --- | --- | --- |
| [2.8.2](releases/2.8.2.md) | 確認済みサマリーに区切り線と Assumption Confirmation を追加すると、本文未変更でも確認が失効する | 対象の装飾的区切り線を除外し、確認を維持する。本文の実質的な変更は引き続き再確認が必要 |
| [2.8.2](releases/2.8.2.md) | レビュー指摘表の列不足・余剰を直す場所が分かりにくい | セル数と期待する列順を表示する。不正な行を直すまでレビュー完了は拒否する |
| [2.8.2](releases/2.8.2.md) | wave で実行中の工程に serial 用 Unit 操作を使えてしまう | `unit start/pause/resume` を状態・監査を変えずに拒否し、`unit complete --wave` を案内する。unit-major に戻した場合も残りの Unit を完了できる |
| [2.8.1](releases/2.8.1.md) | 初期設定で既定値を選べない、同じ版への更新が失敗する、Cursor/Copilot のネイティブフックが動かない | Enter で既定値を受理し、通常の umask でも整合性を確認する。フックの引数を正しく渡し、Cursor の許可時にも有効な JSON を返す |

更新履歴に残る [2.8.6](releases/2.8.6.md) は、上流が保存している未公開の開発履歴です。2.8.6 は公開されておらず、当時の正式な対象版は 2.8.2 でした。現在の同梱対象は 2.11.1 です。

## 2.9.0 へ更新するとき

公式ネイティブ版は `aidlc update` の後、各プロジェクトで `aidlc config --yes` を実行し、`aidlc doctor` で確認します。版を固定する場合は公式インストーラーの `install.sh --version 2.9.0` または `install.ps1 -Version 2.9.0` を使います。手動コピーは Bun 用の `aidlc-copy-runtime-2.9.0.tar.gz` から `runtime/<harness>/` 全体を置き換えてください。

旧 `aidlc-utility.ts change-control` 経路は削除されました。スクリプトは `aidlc engine config set change-control <strict|relaxed>` へ変更してください。`config-change` の未知のフラグはエラーになります。2.9.0 より前のレビューはコミット済みソース証拠がなく、来歴照合では次の Unit レビューまで `unverifiable` です。詳細は[2.9.0 の更新履歴](releases/2.9.0.md)と[導入・更新ガイド](guide/18-install-and-lifecycle.md)を確認してください。

表示している版数は AIDLC Guide に同梱したドキュメントの版数です。対象ワークスペースへのインストール済みバージョンや、AIDLC Guide 拡張自体のバージョンとは別です。
