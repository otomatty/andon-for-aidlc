# PRD: Andon for AI-DLC — aidlc-workflows 可視化・ガイドツール

- **Version**: 0.2
- **Date**: 2026-08-14
- **Status**: 2.6.2 追従（State Version 8）
- **名称**: Andon for AI-DLC（略称 Andon。旧仮称 AIDLC Guide。2026-10-29 決定 → §12）
- **サポート対象**: aidlc-workflows **2.6.2**（State Version **8** / 5 フェーズ・**33** ステージ）。旧 State Version は解析不可（C-T3）

---

## 1. 背景・課題

aidlc-workflows 2.6.2 は 5 フェーズ・33 ステージで構成され、Construction フェーズではユニット × ステージの組み合わせで成果物 Markdown が増殖する（参考: tb-lxp の 1 インテントで約 593 ファイル）。2.6.1 で Application Design は Domain Design に改名され、Contract Design（2.8）が追加された。この構造は監査可能性・再現性のためには正しいが、人間側に次の 3 つの問題を生んでいる。

| # | 課題 | 具体像 |
|---|------|--------|
| P-1 | 現在地がわからない | 経験の浅いエンジニアは「今どのフェーズ・ステージにいて、次に何が来るのか」を `aidlc-state.md` の生テキストから読み解けない |
| P-2 | 成果物が多すぎて把握できない | ユニット × ステージで同名ファイルが複製され、フォルダを眺めても全体像・欠落・薄い箇所が見えない |
| P-3 | 調べ物が本線セッションを汚す | ワークフロー実行中に技術質問・用語質問・実装状況調査をすると、本線の Claude Code セッションの文脈が濁る |

加えて、同じマシンにいない人へワークフローの位置と成果物を届ける必要がある。Dashboard は `127.0.0.1` だけで待受するため、同席できない共有は git 上のレコードを非同期に渡す（P-4）。

## 2. 目的とゴール / 非ゴール

### 目的

aidlc-workflows の経験が浅いエンジニアでも、**現在の状況と今後のステージを迷わず理解でき**、成果物を**読みやすい形で閲覧・共有できる**ローカル開発者ツールを提供する。

### ゴール

- G-1: ワークフローの現在地（フェーズ / ステージ / ユニット / ゲート状態）が 1 画面で把握できる
- G-2: 各ステージの「目的・入出力・担当エージェント・次に人間へ求められること」が初学者向けの平易な解説付きで読める（公式ドキュメントへ deep-link）
- G-3: 成果物 Markdown を WYSIWYG ビューアで閲覧できる
- G-4: 本線のワークフローセッションを汚さず、登録済み MCP とドキュメント質問で、状態・用語・成果物を調べられる。別に起動した Claude Code からも同じ MCP を使える
- G-5: 同じマシンの Dashboard（VS Code / Cursor 拡張の中）でワークフロー状態と成果物を閲覧でき、ファイル変更が画面に反映される。同席できない共有は非同期の git 共有で行う

### 非ゴール

- aidlc-workflows 本体（エンジン・ステージ定義・監査ログ）の変更・置き換え
- 成果物の汎用編集ツール化（監査対象ファイルの手編集は規約違反。編集は質問ファイルの `[Answer]:` 記入のみ）
- クラウドサービス化・アカウント管理（ローカルツールに徹する）
- 複数インテント横断の分析・レポーティング（将来検討）

## 3. 対象ユーザー

| ペルソナ | 状況 | 主なニーズ |
|---------|------|-----------|
| **初学者エンジニア** | aidlc-workflows 経験が浅い | 現在地・次のステージ・用語を自分で知りたい（G-1, G-2, G-4） |
| **ドライバー** | 本線の Claude Code セッションでワークフローを進める | 本線を汚さず調べたい。同じマシンでは Dashboard を見たい（G-4, G-5） |
| **同席できない参加者** | 時間や場所がずれ、レコードだけを受け取る | 非同期 git 共有の成果物を読みたい（G-3, G-5） |

## 4. 全体アーキテクチャ方針

**「1 ライブラリ・2 サーフェス」+ 既製品の活用。**

- 状態の読み取りロジックを 1 つのライブラリ（aidlc-reader）に集約し、Dashboard と MCP サーバーから同じモデルを参照する
- ツールは **読み取り専用** を原則とする（aidlc の成果物はエンジンと監査ログが所有）
- 2026-10-02 以降、Live Share 連携、LAN 公開、セッション分岐の製品ラッパーは現要件に含めない。Dashboard の待受は `127.0.0.1` のみで、ファイル変更の画面反映は WebSocket push で行う
- 調べ物は登録済み MCP とドキュメント質問で行う。別に起動した Claude Code が同じ MCP を使うことは残す

## 5. 機能要件

### F-01: aidlc-reader（状態モデルライブラリ）

- FR-1.1: `aidlc-state.md` をパースし、フェーズ / ステージ進捗（EXECUTE・SKIP・完了・進行中・ゲート待ち）・スコープ設定・ユニット情報を型付きモデルとして提供する
- FR-1.2: インテントの成果物ツリー（`aidlc/spaces/<space>/intents/<record>/`）を走査し、ユニット × ステージ × 成果物種別のマトリクスを構築する
- FR-1.3: 監査シャード（`<record>/audit/`）から直近のイベント履歴（ステージ開始 / 完了 / ゲート / レビュー verdict）を抽出する
- FR-1.4: アクティブインテントの解決（`active-intent` カーソル）と複数インテントの列挙に対応する
- FR-1.5: ファイル監視（state・construction 配下）により、生成中もモデルが追従する

### F-02: MCP サーバー

`.mcp.json` に登録する。本線の Claude Code と、別に起動した Claude Code のどちらからも利用できる。製品のセッション分岐ラッパーではない。

- FR-2.1: `aidlc_status` — 現在のフェーズ / ステージ / ユニット / ゲート状態 / 完了数を返す
- FR-2.2: ~~`aidlc_explain_stage(slug)`~~ — 2026-10-29 に廃止。ステージの解説は文書ツール（`aidlc_docs_search` / `aidlc_docs_read`）で引く
- FR-2.3: `aidlc_next_steps` — 次に来るステージと、そこで人間に求められること（ゲート / 質問）を返す
- FR-2.4: `aidlc_read_artifact(path)` — インテント配下の成果物本文を返す
- FR-2.5: ~~`aidlc_glossary(term)`~~ — 2026-10-29 に廃止。用語は文書ツールで同梱ドキュメントの用語集から引く

### F-03: サイドセッション支援（2026-10-02 に取り下げ）

`btw` ラッパー、Ask (btw)、Ask one-shot、および Claude Code のセッション分岐を包む製品機能は現要件ではない。調べ物は MCP とドキュメント質問で行う。

### F-04: Dashboard（ローカル Web）

- FR-4.1: **Now strip** — フェーズ / 現在ステージ / ユニット / Depth / 完了数（例: 15/22）を常時表示する
- FR-4.2: **Stage rail** — 実行対象ステージを一列に表示し、完了 / 進行中 / ゲート待ち / SKIP を色分けする。クリックでそのステージの成果物・解説・docs へ遷移する
- FR-4.3: **Unit × Stage マトリクス** — 行 = ユニット、列 = Construction ステージ。セルは成果物の有無・件数・レビュー verdict（READY / NOT-READY）を表示する
- FR-4.4: 各ステージカードに初学者向け解説（目的・入出力・担当エージェント・ゲートで求められること）を表示する
- FR-4.5: SKIP ステージは折りたたみ、SKIP 理由（スコープ由来）を表示する

### F-05: Docs Bridge（ドキュメント直結）

- FR-5.1: ステージ slug → 公式ドキュメント該当節（guide / reference）への静的対応表を持ち、Dashboard と MCP（FR-2.2, FR-2.5）の両方が同じ対応表を参照する
- FR-5.2: docs リポジトリの場所は設定ファイルで指定する（ローカル clone のパス）
- FR-5.3: プロジェクト固有ドキュメント（PRD / ADR / team practices）へのリンク欄を設定で追加できる

### F-06: WYSIWYG Markdown ビューア

- FR-6.1: 成果物 Markdown を WYSIWYG 表示する（第一候補: Milkdown / Crepe）
- FR-6.2: 既定は読み取り専用。編集は `*-questions.md` の `[Answer]:` 記入のみ許可する（許可対象はファイル名パターンで制御）
- FR-6.3: Mermaid 図はレンダリングして表示する（成果物に多用されるため）

### F-07: ローカル Dashboard の更新

- FR-7.1: Dashboard は `127.0.0.1` でのみ待受する。LAN 公開、`--host`、参加者向け read-only は 2026-10-02 に取り下げた
- FR-7.2: ファイル監視 → WebSocket push により、状態変化（ステージ遷移・成果物生成）が開いている Dashboard に反映される

### F-08: 運用ガイド（自作コード外の成果物）

- FR-8.1: Live Share 運用ガイドは 2026-10-02 に取り下げた
- FR-8.2: **非同期共有規約** — ゲート承認後に操作者が `git push` を実行する手順と、参加者側の checkout 不要閲覧（`git fetch` + `git show origin/<branch>:<path>`）の手順をまとめる

## 6. 非機能要件

- NFR-1 **読み取り専用原則**: FR-6.2 の質問ファイル編集を除き、ツールは aidlc 配下・リポジトリに書き込まない
- NFR-2 **起動速度**: Dashboard 起動から初回表示まで 3 秒以内（593 ファイル規模のインテントで）
- NFR-3 **追従性**: ファイル変更からビュー反映まで 2 秒以内（ローカル）
- NFR-4 **クロスプラットフォーム**: Windows（Git Bash 環境含む）と macOS で動作する
- NFR-5 **依存最小**: ランタイムは bun のみ。DB 不要（ファイルシステムが唯一の真実のソース）
- NFR-6 **堅牢性**: パース不能な state / 成果物があっても全体は落とさず、該当箇所を「解析不可」として表示する
- NFR-7 **セキュリティ**: Dashboard の listen は `127.0.0.1` のみ。LAN 公開フラグは提供しない

## 7. 技術方針

| 領域 | 選定 | 理由 |
|------|------|------|
| ランタイム / ビルド | bun + TypeScript | aidlc-workflows のツール群と同一。チーム標準 |
| Dashboard | Vite + React | チームの既存スタック（tb-lxp と同じ）で学習コストゼロ |
| WYSIWYG | Milkdown (Crepe) | Markdown ネイティブで往復変換の劣化が最小 |
| MCP サーバー | MCP TypeScript SDK (stdio) | Claude Code 標準の統合方法 |
| ファイル監視 | chokidar | クロスプラットフォームの実績 |
| 画面の更新 | 自作 WebSocket push | ファイル変更を開いている Dashboard に届ける |

## 8. スコープ外（明示）

- aidlc の状態・成果物への書き込み（質問ファイルの `[Answer]:` を除く）
- AI による成果物の自動要約・自動レビュー
- 全文検索エンジン（まず slug → docs 対応表で足りる想定。効かなければ将来追加）
- 複数インテント・複数スペースの横断ビュー
- 認証付きの社外公開ホスティング

## 10. 成功指標

- S-1: 初学者が「現在のステージ・次のステージ・そこで求められること」をツールだけで 1 分以内に説明できる
- S-2: 同席できない参加者が、非同期 git 共有のレコードから、口頭確認なしにワークフローの位置と成果物を読める
- S-3: 本線セッションの `/clear` や文脈汚染を理由とするやり直しが減る（定性）
- S-4: ステージに関する「これ何？」系の質問が MCP / Dashboard で自己解決される割合

## 13. 取り下げの経緯（2026-10-02）

次の製品面は現要件ではない。経緯だけを残す。

- 同期のモブで、参加者全員がドライバーのブランチ状態と、AI とのやりとりをリアルタイムに閲覧する要望があった。想定していた手段は Live Share と、LAN へ Dashboard を公開する参加者向けの読み取り専用モードである。現在、画面の更新は同じマシンで開いている Dashboard（`127.0.0.1`）への WebSocket push だけである。同席できない共有は非同期の git 共有である。
- 本線セッションを汚さない調べ物を、Claude Code のセッション分岐（独立起動、`/branch`、`--fork-session`）を包む製品（`btw`、Ask (btw)、Ask one-shot）で提供する想定だった。`--fork-session` の JSONL は最終フラッシュ時点であり、本線の実行中に直近の会話が含まれないことがあった。当時の緩和は、その制約をヘルプとドキュメントに書き、文脈が必要なときは本線内の `/branch` を案内することだった。現在の調べ物は、登録済み MCP とドキュメント質問である。別に起動した Claude Code が同じ MCP を使うことは残す。これは製品ラッパーではない。
- 状態読み取りの公開面は、Dashboard、MCP サーバー、モブモードの 3 面とする想定だった。現在の公開面は Dashboard と MCP サーバーである。
