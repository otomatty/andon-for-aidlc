# カスタマイズ機能の実装記録

2026-09-15。基本設計・詳細設計で合意した機能を、Andonとaidlc-workflowsの二つのリポジトリへ実装した。公開リリース、利用中のIDEへのインストール、既存プロジェクトの設定への適用は行っていない。

2026-09-16にAIチャットによるカスタマイズを削除。チャット画面、AI実行API、会話管理、提案の取り込みと取り消しを廃止した。

## 2026-09-17の変更

永続下書きと、差分確認後の別操作による適用を削除した。フォームの変更を800ミリ秒の待機後に自動保存し、検証・計画生成・エンジンへの書き込みを一度に行う。保存処理は直列化し、応答待ちの間の追加編集も保持する。対象スペースとプラグインはヘッダーで切り替え、読み込み・書き出しは補助メニューにまとめた。保存失敗時は入力を残す。保存結果が不明な場合は操作の受付記録で復旧し、重複した書き込みを防ぐ。

公開APIは `POST /api/customization/save` に統合した。`draft/*`、`plan`、`apply` の画面向けAPIと下書きストアを廃止した。エンジン内部のvalidate/plan/apply契約は変更していない。読み込み・書き出しは現在の入力をリクエストとして受け取り、下書きを作らない。既存の下書きファイルは自動削除も復元もしない。

以下は2026-09-15時点の実装記録で、下書きに関する記載はこの変更によって置き換えられる。

## 実装範囲

- 最上位の「カスタマイズ」ページと六カテゴリの編集。フォームと原文を切り替え、未知の設定と編集対象外の本文を保持する。
- プロジェクトごとに一つの永続下書き。自動保存、保存失敗時の入力保持、同時編集の競合、外部設定変更との比較に対応する。
- 差分確認後の手動適用。未完了のワークフロー、単独工程、compose等が残る間は正式適用を拒否する。通信断後の結果照会、永続ジャーナルによる復旧を備える。
- Andon JSONの項目選択による取り込みと、Andon JSON・標準プラグインZIPの書き出し。標準プラグインで表現できない置き換えは、除外内容を明示する。
- IDEとローカルブラウザーで共通の操作。画面幅に応じてカテゴリの選択方法を切り替え、編集内容を保持する。

試行機能は設けていない。検証や差分生成が、センサー、ステージ、プラグインの任意コードを実行することもない。

## コードの配置

Andon側は `packages/shared-types/src/customization*.ts`、`packages/api-core/src/customization/`、`packages/dashboard/src/components/customization/` が中心。IDEの更新処理は `packages/vscode-extension/src/native-customization.ts` から共通エンジンを呼び出す。

エンジン側は、隣接する `aidlc-workflows` リポジトリの `core/tools/aidlc-customization*.ts`、既存の起動・更新・読込経路、配布物生成処理を変更した。[共通契約](../../../aidlc-workflows/docs/reference/21-customization-contract.md)にAPIと復旧手順を記載している。検証用コピーから元のチェックアウトへ34ファイルを反映し、各ファイルのSHA-256一致を確認済み。各IDE向けの生成物ではなく、手書きのソースを変更対象としている。

## 導入条件と版の扱い

エンジンの実装基点は利用者のaidlc-workflowsチェックアウト `c4ae1fa9de8b868f81f4f1b6c32055a72a002c8a`。このチェックアウトの版表記は2.8.2だが、公式2.8.2のSHAとは異なる。機能の可否は版番号ではなく、今回追加した契約と全インストール先の整合性で判定する。

Andonが固定している公式2.8.2のSHA `355903d6dc8eb07d3c77180be5d40ed679d6a40f`、同梱ドキュメント、`.claude/`・`.cursor/` は維持した。開発用エンジンの無関係な差分を、この固定配布物へ混入させていない。State Version 8・基本33ステージも変えていない。

公開済み2.8.2では下書き編集とAndon JSONの読み書きを利用できる。対応エンジンがない場合、Andon JSONは基本的な形式を検証して書き出し、参照関係と適用の互換性が未検証であることを表示する。正式適用・標準プラグイン生成を使うには、今回の契約を備えたエンジンのビルドと導入が必要。利用中のIDEへ自動インストールする変更ではない。リリース時には両リポジトリの公開と導入版更新を揃える。

下書きの操作結果は直近1,024件を保持し、再送と結果照会に使う。保持範囲を超えた操作は結果照会で見つからなくなる。再送時も下書きIDとrevisionの一致を確認する。正式適用の復旧記録は、この下書き用の保持上限とは別に管理する。

PR #103のmacOS CIで、ロック起動に使う長いdata URLがBunの`NameTooLong`で拒否される問題を確認した。固定コードを関数として起動する方式に変更し、Windows・macOS・LinuxのCIが成功した。ロック失敗時は元の原因と標準エラーを診断に残す。

既存の工程・エージェント等の識別子とプラグインの所有者は固定とした。別の識別子やプラグイン内のファイル名を使う場合は、新しい項目を追加して古い項目を削除する。参照不足は適用前に診断する。
