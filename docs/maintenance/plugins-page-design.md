# 「プラグイン」画面の設計

状態: 設計を確定（2026-10-15）。未実装。

VSIX に AI-DLC のプラグイン（最初は `focus`）を同梱し、ダッシュボードの新しい最上位画面「プラグイン」から、
開いているプロジェクトへ導入・有効化・無効化・更新できるようにする。画面は「知る → 確かめる → 入れる →
使い始める」の順に並べ、導入する前に価値・前提・追加されるファイルが分かるようにする。

プラグインの中身（`plugins/focus/`）の設計は [Claude Code 向け開発ワークフロープラグイン：設計](claude-code-workflow-plugin-design.md) を参照。

## 決定事項

| 項目                 | 決定                                                                                                                                           |
| -------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| 名称                 | 「プラグイン」。CLI（`aidlc plugin …`）・README・カスタマイズ画面の絞り込みと同じ言葉にする                                                    |
| 置き場所             | ヘッダーのメニューで「ドキュメント」と「カスタマイズ」の間。アイコンは lucide の `PuzzleIcon`                                                  |
| カスタマイズとの分担 | 「プラグイン」は同梱のプラグインを入れて使う画面。自作（所有プラグイン）と書き出しは「カスタマイズ」に残す。導入の機能はカスタマイズに置かない |
| 対象                 | VSIX に同梱したプラグインだけ。任意のフォルダーや ZIP からの導入は扱わない                                                                     |
| 対応ツール           | 導入先は Claude Code（`.claude`）だけ。focus の文書とセンサーが `.claude/` を前提にしているため                                                |
| 導入先の bun         | 使わない。対象はネイティブの `aidlc` で導入したプロジェクトだけ。手動コピー（bun で動く）のプロジェクトは対象外                                |
| 操作できる場所       | VS Code / Cursor の拡張だけ。ブラウザ版は一覧と説明だけを表示し、操作ボタンを出さない                                                          |
| 書き込みの経路       | 拡張は直接書き込まず、ネイティブの `aidlc` CLI（`engine plugin sync` / `engine plugin select`）に任せる                                        |
| 外す操作             | 「無効にする」（`engine plugin select`）。ファイルは残り、再び有効にするとすぐ使える。ファイルの削除は扱わない                                 |
| 作業中の扱い         | 未完了のワークフローがある間は、導入・有効化・無効化・更新を受け付けない（カスタマイズの正式適用と同じ）                                       |
| 表示上の位置付け     | V1（実チケットでの試行）と V7（導入手順）が確認できるまで「試験版」と表示する                                                                  |

## 画面

### ヘッダー

`packages/dashboard/src/shell/Header.tsx` の `destinations` に、ドキュメントとカスタマイズの間へ1件足す。
メニューは3列のグリッドで、6件ちょうど2行になる。

| 項目      | 値                                                              |
| --------- | --------------------------------------------------------------- |
| `id`      | `plugins`                                                       |
| `testId`  | `plugins-open`                                                  |
| `label`   | プラグイン                                                      |
| `icon`    | `PuzzleIcon`                                                    |
| `onClick` | `dispatch({ type: "plugins", open: true })`                     |
| ルート    | `{ name: "plugins" }`（`packages/dashboard/src/app/routes.ts`） |

コマンドパレットにも `aidlc-guide.openPlugins`（`AIDLC Guide: Open Plugins`）を足し、ダッシュボードを開いてこの画面へ移る（段階 2。ダッシュボードを開いたときの画面の指定は、いまは「はじめに」と「更新情報」用の仕組みしかないため、拡張側に手を入れる段階 2 で足す）。

### 一覧

見出しの下に1文を置く。

> AI-DLC に、決まった進め方を追加します。自分で作る場合はカスタマイズへ。

同梱プラグインをカードで並べる。カードには次を表示する。

- 名前・版・「試験版」の印
- 一文の約束（例: 「Jira チケット1枚から、テストを先に書いて実装まで。説明は図で。」）
- このプロジェクトでの状態（下記「状態」）
- 主な操作ボタン1つ（状態ごとに決まる）

### 詳細

カードを開くと、同じ画面の中で詳細を表示する。上から順に4つの区画を置く。

1. **何が変わるか**
   - 標準の進め方とプラグインの進め方（focus は `focus-flow`）のステージを横に並べて比べる。プラグインが足すステージ（`focus-test`・`focus-implement`）と、手順を追記する標準ステージに印を付ける。
   - 成果物の見本（focus は図を中心にした要件・設計の1枚）を表示する。
   - 合う人・合わない人（focus は「Claude Code を使う」「Jira で管理している」）。
2. **前提の確認**: 下記「前提の確認」の結果を一覧にし、満たしていない項目には直す手段を隣に置く。
3. **追加・変更されるファイル**: 追加されるファイルと、手順が追記される標準ステージのファイルを一覧にする。アプリケーションのコードは変えないことを明記する。導入後は、実際に変わったファイルを git の差分で示す。
4. **操作**: 状態に応じたボタン（導入する・有効にする・更新する・無効にする）。実行中は進み具合と取り消しボタンを表示する。

導入が終わったら「使い始める」を表示する。

- チケット番号と要約を入力すると、`/aidlc --scope focus-flow PROJ-123 <要約>` をクリップボードにコピーする。
- 「進め方のガイドを開く」で、導入された `.claude/knowledge/aidlc-shared/focus-flow-guide.md` をエディタで開く（既存の `open-file`）。

### ブラウザ版

一覧・詳細の「何が変わるか」「追加・変更されるファイル」は表示する。前提の確認と操作ボタンは出さず、
「導入は VS Code / Cursor の拡張から行えます」と案内する（設定画面と同じ扱い。押しても何も起きないボタンを置かない）。
一覧と詳細は、ダッシュボードに組み込んだカタログ（下記「カタログ」）から作るため、ブラウザ版でも同じものを表示できる。

### 状態

プロジェクトの `.claude/` を読んで、プラグインごとに次の状態を決める。判定は純関数にする。

| 状態     | 条件                                                                                                                                | 主な操作                  |
| -------- | ----------------------------------------------------------------------------------------------------------------------------------- | ------------------------- |
| 未導入   | `plugin-compose-<name>.json` がない                                                                                                 | 導入する                  |
| 有効     | 記録があり、`harness.json` の `plugins` に含まれる（`plugins` がなければ全件有効とみなす）                                          | 無効にする                |
| 無効     | 記録はあるが、`plugins` に含まれない                                                                                                | 有効にする                |
| 更新あり | 有効または無効で、記録の `version` か `sourceHash` が同梱物と違う                                                                   | 更新する                  |
| 要確認   | 導入の記録が読めない、`aidlc/.plugin-compose-retry-<name>` がある、または有効なのに `stage-graph.json` にプラグインのステージがない | 更新する（Doctor を案内） |

判定は `packages/vscode-extension/src/plugins-state.ts`。ファイルを読むだけで決め、CLI は動かさない（画面を開くたび、フォーカスが戻るたびに読むため）。
合成の失敗記録（`plugin-compose-<name>.drops`）は、置き場所が作業中のインテントで変わるため読まない。代わりに、有効なのにステージがない状態を「要確認」にする。
前提を満たさないとき（Claude Code が未設定、バージョン確認が `ok` でないなど）は、状態ではなく「必要なもの」に出し、操作ボタンを押せなくする。

## 前提の確認

導入ボタンを押せるのは、必須の項目がすべて満たされているときだけにする。

| 項目                                                      | 区分 | 満たしていないときの案内                                                                                                                |
| --------------------------------------------------------- | ---- | --------------------------------------------------------------------------------------------------------------------------------------- |
| ワークスペースを信頼している                              | 必須 | 信頼の設定を開く                                                                                                                        |
| バージョン確認が `ok`（エンジンが対応版であることを含む） | 必須 | 更新画面を開く（`ok` でなければ画面ごとブロックされる）                                                                                 |
| Claude Code（`.claude`）が設定済み                        | 必須 | セットアップの「ツールを追加」を開く                                                                                                    |
| Claude Code 以外のツールの AI-DLC がない                  | 必須 | 同梱のプラグインは Claude Code 向けだけで、ほかのツールとプラグインの構成が食い違うと以後の追加・更新が止まるため導入できないと表示する |
| 未完了のワークフローがない                                | 必須 | 「いまの作業を終えてから導入してください」と表示する                                                                                    |
| 別の導入・更新が実行中でない                              | 必須 | 終わるまで待つよう表示する（`acquireWorkflowsOperation`）                                                                               |
| ネイティブの `aidlc` で導入したプロジェクト               | 必須 | 手動コピーのプロジェクトでは、セットアップでネイティブに移す案内                                                                        |
| Atlassian の MCP サーバーが `.mcp.json` にある            | 推奨 | 登録手順へのリンク。なくても、チケット本文を貼り付けて進められる                                                                        |
| Claude Code のモデルが Opus                               | 案内 | Construction のステージが Opus を求めることを表示する                                                                                   |

モデルは拡張から確かめられないため、判定せず案内だけを表示する。

ネイティブかどうかは、バージョン確認と同じく `tools/data/aidlc-stamp.json` の有無で判定する（[バージョン確認の設計](version-gate-design.md)）。
focus は bun を使わないため、導入先に bun があるかは確かめない。

## 同梱

### ビルド

`build:extension` に、同梱プラグインを作る手順を足す。

```sh
bun .claude/tools/aidlc-plugin-build.ts plugins/focus claude packages/vscode-extension/dist/plugins/focus/claude
```

- ネットワークは使わない。リリースの CI（`bun` だけを入れる）でもそのまま動く。
- bun を使うのは Guide のビルドのときだけ（開発時の作業）。利用者のプロジェクトには bun は要らない。
- `!dist/**` が `.vscodeignore` で残るため、VSIX に入る。
- 出力は `.claude-plugin/plugin.json`、`hooks/compose.ts`、`stages/` などのプラグインの出力一式。`tests/` と `README.md` は入らない。
- 大きさは 1 プラグインで約 0.5 MB。VSIX の大きさの上限は設けない（NFR が予算を決めるまで）。

### カタログ

`scripts/build-bundled-plugins.ts`（`bun run build:plugins-catalog`）が、カタログ `packages/shared-types/src/bundled-plugins.generated.json` を作る。
カタログはリポジトリにコミットし、ダッシュボードと拡張の両方がビルド時に取り込む（`BUNDLED_PLUGINS`）。ブラウザ版のための API は設けない。
`bun run check` の `check:plugins-catalog` が、一時フォルダーで作り直した結果とコミット済みのカタログを比べ、違えば失敗にする（`check:docs-index` と同じ考え方）。

カタログは、プラグインを実際に組み込んだ結果から作る。`plugins/<name>/` ごとに、エンジンの `aidlc-plugin-build.ts` でビルドし、
このリポジトリが追跡している `.claude/` の写しに、エンジンの `engine plugin sync` と `engine plugin select` で組み込む。1 プラグインで約 3 秒。

| 項目           | 出所                                                                                                        |
| -------------- | ----------------------------------------------------------------------------------------------------------- |
| 名前・版       | ビルド結果の `.claude-plugin/plugin.json`                                                                   |
| `sourceHash`   | 組み込んだ後の `plugin-compose-<name>.json`（エンジンが計算した値。`sha256:` 付き）                         |
| 表示用の文言   | `plugins/<name>/.aidlc-guide/listing.json`（下記）                                                          |
| ステージの比較 | 組み込んだ後の `stage-graph.json` と `scope-grid.json`。標準ステージへの追記は `contributions/` の `target` |
| 見本の図       | `listing.json` が指す SVG。focus のセンサーと同じ `checkSvg` で検査してから取り込む                         |
| ファイル一覧   | 組み込む前後の `.claude/` の差分（追加と変更）                                                              |

ファイル一覧は `.claude/` の中だけにする。`engine plugin select` は AI-DLC の記録（`aidlc/`）に選択を変えた記録を 1 行書くが、
そのファイル名はマシンごとに違うため、一覧には載せず、画面で文章で伝える。

`listing.json` は Guide のための表示情報で、プラグインの `sourceHash` の対象外（`agents`・`stages` などの外）に置く。

```json
{
  "title": "focus",
  "tagline": "Jira チケット1枚から、テストを先に書いて実装まで。説明は図で。",
  "status": "preview",
  "harness": "claude",
  "scope": "focus-flow",
  "summary": "（プラグインの説明）",
  "fitFor": ["Claude Code で AI-DLC を使っている", "Jira でチケットを管理している"],
  "notFitFor": ["Claude Code 以外のツールだけを使っている"],
  "requirements": [
    { "id": "atlassian-mcp", "level": "recommended", "label": "Atlassian の MCP サーバー", "detail": "…" }
  ],
  "startCommand": "/aidlc --scope focus-flow <チケット番号> <要約>",
  "sample": { "file": "sample/requirements-overview.svg", "alt": "見本: …" }
}
```

`requirements[].level` は `required`（満たさないと導入できない）・`recommended`・`info`。見本の SVG は
`<img src="data:image/svg+xml;...">` で表示し、ページの中にスクリプトとして埋め込まない。

### 版をまたいだ保持

導入の記録（`plugin-compose-<name>.json`）は版と `sourceHash` を固定する。後で「ツールを追加」を行うと、
`capturePluginInputs` がこの値と一致する元パッケージを探す。拡張の更新で拡張のフォルダーが変わると、古い元パッケージが見つからず、ツールの追加が止まる。

そこで、導入するときに元パッケージを拡張のグローバル保存領域へ写し、そこを探す場所に加える。

- 保存先: `context.globalStorageUri/plugins/<name>/<version>-<sourceHash 先頭12桁>/`
- 写した後に `sourceHash` を計算し直し、カタログと一致しなければ導入を止める。
- `findPackage`（`packages/vscode-extension/src/native-plugin-inputs.ts:138-196`）の探す場所に、この保存先を足す。保存先は `capturePluginInputs` と `configureNativeHarness` の引数で渡す。
- 保存した元パッケージは消さない（1 版で約 0.5 MB）。

## 導入の流れ

拡張のホスト側に `plugins-controller.ts` を置く。ダッシュボードからのメッセージを受け、既存のセットアップ・更新パネルと同じ守りで CLI を動かす。

- ルートはメッセージから受け取らず、ホストが持つ `workspaceRoot` を使う。
- 実行の直前に、信頼・フォルダー・バージョン確認を確かめ直す。
- `acquireWorkflowsOperation` で他の導入・更新と直列にする。
- 実行中は `busy` とし、重ねて届いた操作は受け付けない。`AbortController` で取り消せるようにする。
- CLI の環境変数は `applyCandidatePlugins` と同じ扱いにする（`CLAUDE_PLUGIN_ROOT` などを消し、`AIDLC_HARNESS_DIR=.claude`、`AIDLC_HARNESS_NAME=claude` を渡す）。この部分は共通の関数に切り出す。

### 導入する

1. 前提の確認をやり直す。
2. git の状態を記録する（`gitStatusSnapshot`）。
3. 元パッケージを保存領域へ写し、`sourceHash` を確かめる。
4. `aidlc engine plugin sync --project-dir <root> --json` を、`AIDLC_PLUGIN_ROOT=<保存先>` で実行する。
5. いまの選択（`harness.json` の `plugins`。なければ `aidlc` と組み込み済みのすべて）に `<name>` を加えて、`aidlc engine plugin select <名前の一覧> --project-dir <root>` を実行する。更新では選択を変えない（無効のまま更新したプラグインは無効のまま）。
   続けて、ネイティブの `aidlc-manifest.json` の既存の行を、書き換わったファイルの内容に合わせる（ツールの追加のときと同じ `refreshNativeManifest`。マニフェストのないプロジェクトでは何もしない）。
6. 導入できたことを確かめる。`stage-graph.json` にプラグインのステージがあること、`plugin-compose-<name>.json` の版と `sourceHash` が同梱物と一致すること、合成の失敗記録がないこと。どれかが満たされなければ失敗として扱う（`.claude/tools/aidlc-graph.ts` がないと合成が何も言わずに終わるため、成功の出力だけを信じない）。
7. git の状態を再び記録し、変わったファイル（最大30件と「ほか N 件」）と、コピーできるコミットメッセージ（例: `chore: AI-DLC プラグイン focus 0.1.0 を導入`）を表示する。

### 有効にする・無効にする

`aidlc engine plugin select <名前の一覧>` だけを実行する。無効にすると、追記した手順・スコープ・ランナーが外れ、
コピーしたファイルは残る。画面では「ファイルは残ります。もう一度有効にすると、すぐに使えます」と表示する。

エンジンは、無効にしたプラグインのステージも `stage-graph.json` に残し、実行時に `harness.json` の選択で絞り込む。
そのため無効化は「選択から外れたこと」で確かめ、有効化は「選択に入り、ステージ構成にステージがあること」で確かめる。

エンジンは、プラグインのスコープを使う未完了のワークフローがあると無効化を拒否する。その場合は拒否の理由をそのまま表示する。

### 更新する

「導入する」の 3〜7 と同じ。`sync` が以前のファイルを確かめてから置き換える。手で編集されたファイルがあると
`sync` は拒否するため、拒否されたファイル名を表示し、元に戻すよう案内する。

### 失敗したとき

- CLI の終了コードが 0 でなければ、`--json` の `message` を日本語の状態表示に変えて出す。`sync` は失敗時に元へ戻すため、途中の状態は残らない。
- `select` を始めた後に止まったとき（6 の確認の失敗、マニフェストの更新の失敗、取り消し）は、選択を元に戻し（`select` を導入前の一覧で実行）、Doctor を案内する。元に戻す `select` が失敗したら、マニフェストは更新せず「選択を元に戻せませんでした」として Doctor を案内する（取り消しの途中でも、取り消し扱いにしない）。
- 取り消したときは、いま動いている CLI を止めて「取り消しました」と表示し、状態を読み直して画面に出す。
- 操作の前に、プロジェクトのフォルダーがまだ開かれているかを確かめる。閉じたフォルダーの古い画面からは操作しない。

## 通信

操作は拡張の CLI を使うため、api-core のルートではなく、ダッシュボードと拡張の間のメッセージで行う。
メッセージの型は `packages/shared-types/src/plugins.ts` に置く（いまは型のないメッセージが多いが、新しいものは型を付ける）。

| 方向        | メッセージ           | 内容                                                               |
| ----------- | -------------------- | ------------------------------------------------------------------ |
| 画面 → 拡張 | `plugins-get`        | カタログ・状態・前提の確認を求める                                 |
| 拡張 → 画面 | `plugins-state`      | `PluginsState`（カタログ、状態、前提の確認）                       |
| 画面 → 拡張 | `plugins-action`     | `{ action: "install" \| "enable" \| "disable" \| "update", name }` |
| 画面 → 拡張 | `plugins-cancel`     | 実行中の操作を取り消す                                             |
| 拡張 → 画面 | `plugins-progress`   | 進み具合（手順の番号・文言）                                       |
| 拡張 → 画面 | `plugins-result`     | 結果（成功・失敗・取り消し、変わったファイル、コミットメッセージ） |
| 画面 → 拡張 | `plugins-copy-start` | 「使い始める」のコマンドをクリップボードへ                         |

画面は設定画面と同じく `window` の `message` を受け、フォーカスが戻ったときに `plugins-get` を送り直す。
カタログは画面に組み込まれているため、ブラウザ版は通信をしない。バージョン確認でブロックされている間は、画面そのものを表示しない（ナビゲーションが差し替わる）。

## 既存の制約との関係

- **読み取り専用の原則:** Guide は `aidlc/` と `.claude/` に直接書き込まない。書き込みはエンジンの CLI が、エンジンの手順（ロック・取り消し・監査の記録）で行う。セットアップ・更新・カスタマイズの保存と同じ扱いで、利用者が画面で操作したときだけ動く。
- **出荷ランタイム:** 追加するのはプラグインの出力（Markdown と、エンジンが動かす TypeScript）だけで、拡張の実行時ランタイムは増えない。
- **パス:** すべて `node:path` / `vscode.Uri` で組み立てる。
- **パッケージ衛生:** 同梱物に秘密情報・`.env`・`aidlc/` の実行時状態が入らないことをテストで確かめる。

## テスト

チームの方針どおり、失敗するテストを先に書く。すべて `bun run check` に含める。

| 対象                     | 内容                                                                                                                                 |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------ |
| 状態の判定（純関数）     | 6 つの状態それぞれと、`plugins` がない場合・記録が壊れている場合                                                                     |
| 前提の確認（純関数）     | 必須・推奨・案内の区分と、ボタンを押せるかの判定                                                                                     |

残る注意点:

- focus は Claude Code 向けにだけビルドしている。focus を入れたプロジェクトに、あとで別のツール（Cursor など）を「ツールを追加」で足すと、既存のプラグインをそのツール向けに作り直せず、追加が止まる（既存の安全装置の動き）。逆に、すでに別のツールの AI-DLC があるプロジェクトには導入できない（前提の確認で止める）。
- 同梱の focus を拡張の更新で新しくした場合、画面は「更新あり」を表示する。更新しない間も、保存領域の古い版でツールの追加は通る。
