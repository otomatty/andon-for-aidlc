# Dashboard で現在地と成果物を読む

> 対象: 日常的に AI-DLC の進捗を確認する開発者  
> 関連: [はじめに](./getting-started.md) · [設定ファイルでプロジェクトリンクを足す](./configuring-docs.md)

## このガイドでできるようになること

Dashboard 上で「今どこか」「次に何を承認するか」「どのユニットがどの成果物を出したか」を読む。

## 画面の見方

### Now strip（上部）

| 表示                    | 意味                               |
| ----------------------- | ---------------------------------- |
| フェーズ / 現在ステージ | `aidlc-state.md` 上の現在地        |
| 深度（Standard など）   | ワークフローの深さ                 |
| ステータスチップ        | completed / awaiting-approval など |
| `done / total`          | 進捗                               |
| 次の承認まで            | 次の承認ゲートまでの推定作業時間   |

アクティブなインテントが無いときは、ここに空状態とインテント一覧への導線が出ます。

### ステージ一覧（左、狭い画面では上）

- フェーズ見出し（INITIALIZATION → … → OPERATION）の下に、実行順のステージが並ぶ
- 番号付きラベル（例: `1.1 intent-capture`、`4.6 performance-validation`）
- SKIP も折りたたまず、同じ並びに `skipped` として出る
- クリックすると詳細パネルが開く（画面幅いっぱい）

時間の表示は監査ログのイベント間隔から算出します。完了後の作業時間、所要時間の推定、経過と残りの違い、次の承認ゲートの位置の決め方は[ステージ時間の算出方法](./stage-timing.md)を参照してください。昼休憩や翌日への持ち越し、承認待ちの扱いも図解しています。

### 成果物マトリクス（右、狭い画面では下）

- 行 = ユニット、列 = ステージ
- セルの件数・`READY` などはサーバが返した値をそのまま表示
- 「凡例」ボタンでステータス記号の説明をダイアログ表示
- セルをクリックすると、そのユニット×ステージの成果物ビューアが詳細パネルに載る

### 詳細パネル

- ✕ 閉じる / Esc / 外側クリックで閉じる
- ステージ解説: 目的・入出力・担当エージェント・ゲート要求
- 現在ステージなら「次に進むと」コールアウト
- 「Open in Docs」: 同梱の公式ドキュメントの該当ページを開く
- 成果物 Markdown: コードフェンスはシンタックスハイライト、`mermaid` は図

### ヘッダーまわり

| 操作         | 内容                                                        |
| ------------ | ----------------------------------------------------------- |
| Space        | 作業スペースと使用するツールを選び、AI-DLC 本体で切り替える |
| インテント   | クリックで一覧ダイアログを開き、Andon に表示する案件を選ぶ  |
| テーマ       | ライト ↔ ダークをワンクリック                               |
| Live 表示    | 接続状態 / 最終更新                                         |
| projectLinks | `andon.config.json` の追加リンク                            |

### Space を切り替える

左上の「Space: 名前」を開き、既存の Space と使用するツールを選んで「切り替える」を押します。インテントがまだない Space も選べます。複数のインテントがある場合は、続けて表示する案件を選びます。表示中の案件は Space ごとに保持します。

切り替えは、選んだツールに設定済みの AI-DLC 本体を通して実行します。ネイティブ版を導入した環境では Bun は不要です。ソース版のツールを配置した環境では Bun が必要です。プロジェクトにバージョンを固定している場合は、そのバージョンの本体を使用します。

ワークスペースの `aidlc/active-space` が変わり、各ツールが読む手順のコピー `aidlc/active-memory/`（Git の対象外）が新しい Space の `memory/` の内容に更新されます。aidlc-workflows 2.11.1 以降、ツールのルール参照（`.claude/rules/aidlc.md` など）はこのコピーを指したまま変わらず、追跡対象のファイルは書き換えません。進行中のチャットのセッションは保持されるため、そのチャットの作業先も変える場合はチャット内で `/aidlc space <名前>` を実行してください。

信頼されていないワークスペースでは切り替えられません。カスタマイズに未保存の変更や処理中の保存がある場合も、保存・復旧を終えるか変更を取り消してから切り替えてください。外部から Space を切り替えた場合、Andon は表示を更新し、カスタマイズの入力と編集対象は保持します。カスタマイズ画面の「Space」は、編集対象だけを選ぶ操作です。

Space の作成・削除はこの画面の対象外です。Space 切り替えと隣のインテント選択は別の操作で、インテント選択は Andon の表示だけを変更し、`active-intent` を書き換えません。

## 典型的な流れ

1. **`Andon: Open`** で Dashboard を開く
2. Now strip でゲート待ちなら、承認すべき内容を確認する
3. マトリクスで気になるセルを開き、成果物を読む
4. 用語やステージの意味が分からなければ [MCP](./side-questions.md) に逃がす（本線セッションを汚さない）

## 読取専用であることの意味

Dashboard はワークフロー状態を**書き換えたふりをしません**。

- チャットのインテント切替は Claude Code の `/aidlc intent <名前>`。Andon の選択は表示だけを変える
- ゲート承認・ステージ進行は aidlc-workflows 本体側
- 書き込みを伴う操作: AI-DLC 本体による Space 切り替え・カスタマイズ保存、成果物内 `[Answer]:` 行への回答送信、Setup 時の `.mcp.json` マージ

## 狭い画面

幅が狭いときはステージ一覧とマトリクスが縦並びになります。ステージ一覧は件数に応じて伸び、ページ全体でスクロールします。
