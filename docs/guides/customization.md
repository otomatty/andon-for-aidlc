# 開発ルールとステージをカスタマイズする

ヘッダーの「カスタマイズ」から現在の設定を読み込み、フォームで編集すると自動保存します。下書きの保存・復元や、別途「適用」する手順はありません。

## 利用できる環境

VS Code / Cursor内のAndonで利用できます。保存にはBunが必要です。IDEではワークスペースを信頼していることも必要です。

設定の保存には、カスタマイズ契約に対応するaidlc-workflowsエンジンが必要です。版番号ではなく対応機能を確認します。未対応の場合は閲覧・画面内の編集・Andon JSONの読み書きを利用でき、自動保存時に対応エンジンが必要なことを表示します。

## 編集する

1. 「カスタマイズ」を開き、対象スペースを選びます。
2. トップの概念図からカテゴリのカードを開き、一覧のカードから詳細へ進みます。一覧では「すべて / 自作 / 標準」と名前で絞り込めます。
3. ヘッダーで対象スペースとプラグインを選び、内容を編集します。プラグインを選ぶと、その自作項目と参照用の標準設定を表示します。
4. 入力が800ミリ秒途切れたら整合性を検証し、設定へ自動保存します。保存中の追加編集も保持し、順番に保存します。エラーがあれば入力を残して表示します。

| カテゴリ     | 主な編集対象                                                     |
| ------------ | ---------------------------------------------------------------- |
| 開発ルール   | 組織・チーム・プロジェクト・フェーズのルール、ルールファイル設定 |
| ナレッジ     | エージェントが参照する資料、文書原本とDocumentKBの参照           |
| スコープ     | 標準スコープをベースにした自作スコープと実行ステージの選択       |
| ステージ     | 自作ステージ、成果物テンプレート                                 |
| エージェント | 担当者の定義、ステージへの割り当て                               |
| 品質チェック | センサーの定義、対象、関連するスクリプト                         |
| プラグイン   | 配布名・バージョン・依存関係など                                 |

右上の「AIと相談」を押すと、AI チャットが「カスタマイズ」の用途で開き、変えたいことを対話で相談できます。AI が示した変更案は、差分を確認して「この変更を適用」を押すと、この画面の自動保存と同じ検証を通して保存します（[対話でカスタマイズする](asking-aidlc.md#対話でカスタマイズする)）。

フォームが扱わない設定は「原文」で編集できます。標準のスコープ・ステージ・エージェント・品質チェックは、原文を含めて閲覧のみです。解析できない原文や参照先が欠けた設定は、修正するまで保存できません。

別画面やIDEで設定が変更された場合は、自分の入力と現在の設定を比較してから保存します。保存に失敗した場合は、エラー表示から再試行または未保存の変更の取り消しができます。ページの再読み込みや終了では未保存の内容が失われるため、変更がある間は離脱時に確認します。

## 自作スコープとステージ

スコープ一覧の「＋ 標準スコープを複製して作る」から、ベースのスコープ・名前・所有プラグインを指定します。プラグインが未作成なら同時に作成します。

スコープ詳細は「スコープ設定」を最初に表示します。「スコープ設定」と「実行するステージ」のタブで、設定・本文と実行ステージの表を切り替えます。ランナーと自由記述の既定スコープも通常の設定項目として表示します。標準スコープの本文は「日本語」が初期表示で、「英語」に切り替えて確認できます。日本語は表示用で、設定の原文を書き換えません。自作スコープは入力した本文を使います。標準の原文が変わり、対応する日本語がない場合は原文を表示します。

スコープとステージの本文は、見出し・太字・リストなどを整形したまま扱うMarkdownエディターで表示します。ツールバーは表示しません。標準設定では本文の編集を無効にします。自作設定では本文を編集でき、Markdownとして自動保存します。

「実行するステージ」では、フェーズごとの表で実行ステージを選びます。標準ステージの選択はプラグインの `adds.scopes` として保存され、標準ファイルを書き換えません。初期化の3ステージは常時実行で、チェックを外せません。前提ステージがSKIPでもエラーにはなりません。循環や存在しない前提ステージは保存時に表示します。

各フェーズの「＋ ステージを追加」で自作ステージを追加できます。slug・フェーズ・担当・前提ステージを指定し、成果物名にはプラグインの接頭辞が付きます。標準ステージを前提に選べます。標準ステージを自作ステージの後に待たせる操作はありません。

表のステージを押すと、右側に詳細を開きます。幅760px未満では画面全幅に表示します。標準ステージの本文には「英語 / 日本語」の切替があります。日本語は同梱リファレンスの該当節で、同梱版と未翻訳の節は画面に注記します。

## 開発中の画面を確認する

リポジトリのルートで二つのターミナルを開きます。

```sh
bun packages/dashboard-server/src/cli.ts --port 4173
bun run vite packages/dashboard --port 5173 --strictPort
```

`http://127.0.0.1:5173` を開き、ヘッダーの「カスタマイズ」を選びます。画面の変更は自動反映されます。APIの変更を反映するには最初のコマンドを再起動します。Viteは標準の開発用Nodeプロセスで起動し、APIの実行にはBunを使います。

## 他のプロジェクトへ配布する

「書き出す」で項目と配布形式を選びます。

| 形式                  | 用途                                                                     |
| --------------------- | ------------------------------------------------------------------------ |
| Andon用の設定ファイル | ルールの章などを含め、Andon同士で設定を移す                              |
| 標準プラグインのZIP   | 標準プラグインで表現できる追加定義と、選択したツール向けの出力を配布する |

標準プラグインで表現できない設定は表示され、除外を確認してから書き出します。必要な依存先を選択していない場合は、診断に従って選択を見直してください。

ヘッダーの「その他の操作」に読み込み・書き出しとプラグイン管理をまとめています。受け取ったAndon用ファイルは「設定ファイルを読み込む」で比較し、必要な項目と取り込み先を選びます。選んでいない項目やほかの編集内容は保持されます。取り込み後は自動保存します。書き出しは未保存の編集内容からも行え、設定への保存は伴いません。

## 保存と復旧

変更は今後開始するワークフローに使います。設定を共有するスペースに未完了の作業がある間はエンジンが保存を拒否します。一時停止、承認待ち、単独ステージ、構成案の確認待ちも対象です。画面内の編集とAndon JSONへの書き出しは続けられます。

保存の応答が途切れた場合は結果を再確認します。「復旧が必要」と表示された場合は、画面から復旧操作を行ってください。設定ファイルや復旧記録を手動で削除せず、同じ保存操作の結果を確定させます。

検証と差分生成は設定の整合性を調べる処理です。試行用ワークフローを起動したり、センサーや任意のプラグイン処理を実行したりする機能はありません。

保存操作の受付記録は `aidlc/guide-customization/.local/`、適用の復旧記録は `aidlc/.aidlc-customization/` に保存され、Gitの対象外です。保存済みの変更定義とプロジェクトのルール・資料はGitで共有できます。

旧版が作成した下書きファイルは自動で読み込んだり設定へ反映したりしません。既存のファイルは削除せず残します。
