# aidlc-workflows の更新で問題が見つかったとき

更新画面は、更新の前に作業用コピーで公式の更新処理（`aidlc config` の確認）を全ツールに試し、そのままでは更新できないファイルを見つけます。見つかった場合は「更新前のチェック」の手順で止まり、ファイルごとに「何が起きたか」と「どう直すか」を示します。

## ボタン 1 つで直して更新する

問題のあるファイルは、直し方で 4 つに分けて表示します。

| 区分               | 内容                                                                                       | 例                                                                                                                                    |
| ------------------ | ------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------- |
| 自動で直します     | Andon が答えを決められるもの。AI は使いません                                              | 公式ファイルと同じ内容、以前の公式版に足した変更の当て直し、古い区切りの `.gitignore`・Markdown、管理ブロックの付け直し、ツールの順番 |
| 確認してください   | 内容を置き換える・消す・取り寄せるもの。おすすめを選んであり、変えたい場合だけ選び直します | 以前の公式版が手元になく変更部分を見分けられないファイル、新しい版でなくなったファイル、UTF-8 ではないファイル                        |
| AI が直します      | 決まった答えがなく、AI の修正案が必要なもの。反映する前に差分を見せます                    | 書式が壊れた JSON                                                                                                                     |
| 手で直してください | Andon からは直さないもの。直してから「直したので再チェック」を押します                     | リンクやフォルダーになっている場所、区切りの壊れた管理ブロック、チームの記録や管理記録                                                |

「手で直してください」がなければ、主ボタンは「N 件を直して（対応版）に更新」です。押すと次の順に進みます。

1. 「確認してください」で選んだ方法と、自動で直す方法を、作業用コピーに当てます。「以前の公式ファイルを取り寄せる」を選んだ場合は、先に公式インストーラーで以前の版を取り寄せます。この PC の既定のバージョンは変えません。
2. AI が直すファイルがあれば、ファイルごとに AI に修正案を頼みます。
3. 作業用コピーで、公式の更新処理を全ツールに実行し、競合がなくなったことを確かめます。
4. AI が直したファイルがあれば、ここで止まり、差分と AI の説明、Andon による確認結果を示します。「この内容で（対応版）に更新」を押すと続けます。「この修正を使わない」で元の一覧に戻れます。
5. 変わるファイルをバックアップしてからプロジェクトに反映し、そのまま更新と全ツールの Doctor まで続けます。

作業用コピーで直しても残った問題があれば、何も反映せずに一覧へ戻り、そのファイルに「前回の対処のあとも、公式の更新処理が受け付けませんでした」と示します。取り寄せに失敗した場合や、AI が直せないと判断した場合も、ファイルごとに理由を示します。

## AI の使い方

- AI を使うのは「AI が直します」のファイルと、「確認してください」で AI の当て直しを選んだファイルだけです。自動で直せるファイルには使いません。
- AI に送るのは、そのファイルの内容（当て直しでは新旧の公式ファイルも）とエラーの位置だけです。CLI のツールを使わない設定で起動し、その CLI のログインと利用枠を使います。
- AI の修正案は、Andon が決まった規則で確かめます。JSON は「JSON として読める」「キー・値・コメントを同じ順番のまま残し、変えたのは記号と空白だけ」（数値や true / false を変える案、並びを変える案は使いません。引用符が足りない場合は AI では直さず、手で直すよう案内します）、当て直しは「公式版にも今のファイルにもない行を書いていない」を満たさない案は使いません。公式版の行を削った場合などは、確認結果に「!」で示します。
- 各ファイルの「AI に聞く」は、ファイルの中身を送らずに、問題の種類と Andon の案内から、なぜ起きたかとどれを選ぶとよいかを説明してもらいます。ファイルは変えません。
- 使える AI がない場合、AI でしか直せないファイルは「手で直してください」に入ります。Claude Code、Cursor、GitHub Copilot CLI のいずれかを導入・ログインしてから「直したので再チェック」を押すと、AI の検出もやり直します。

## 自動で直す範囲

- 現在のファイルが、以前の版または更新対象版の公式ファイルと一致する場合は、公式の更新処理で作り直します。LF と CRLF の違いは許容します。
- 以前の版の公式ファイルに変更を足したファイルは、いったん公式版に戻して更新し、更新の後で変更を当て直します。新しい版の変更と同じ箇所を変えている場合は「確認してください」に入ります。
- 古い区切りの `.gitignore` は、除外ルールと区切りの外の行を順序どおり残して、新しい管理ブロックへ移します。古い区切りの Markdown は、区切りの外の文章を残して、各ツールの公式の管理ブロックに置き換えます。
- `.gitignore` の管理ブロックに記録がない、または変更されている場合は、同じ位置に公式の内容で付け直し、ブロックの中に足したルールはブロックのすぐ後ろ（公式のルールより優先されては困る場合はすぐ前）にまとめて移して残します。`!` の否定ルールがどちらに置いても公式のルールとの優先順位を変えてしまう場合は、付け直さずに止まり、そのルールを動かすよう案内します。
- 別のツールの共有部分が先に必要な場合（`is missing its shipped block copy` など）は、そのツールを先に更新します。
- 公式の `.gitignore` に、既存の設定にない一般的な除外ルールが含まれる場合は、そのファイルを直さずに止まります。更新のためだけに除外ルールを追加しません。
- 管理記録を Andon が作ることはありません。管理記録は公式の更新処理が作ります。`--force` は使いません。「公式版に置き換える」は、今のファイルをバックアップに移してから公式の更新処理で作り直す方法で、上流の案内と同じ手順です。

リンク先の設定ファイルや確認できないバージョンなど、通常の更新が拒否する状態を回避することはできません。進行中のワークフローがあっても更新はでき、作業はそのまま続けられます（aidlc-workflows 2.11.0 から）。現行の 2.11.1 へは、2.8.0 以降のどの版のプロジェクトからも、合成済みのプラグインがあっても止まらずに更新できます。完了済みのステージの動作が更新で変わっても、そのステージのやり直しは求められません。

## 更新が止まったとき

更新処理の事前確認で止まった場合は、自動で更新前のチェックをやり直し、止まった原因のファイルを同じ区分で示します。主ボタンは同じ更新のやり直しではなく、「N 件を直して（対応版）に更新」になります。

更新後の Doctor で項目が残った場合は、ツールごとに「問題あり」「要確認」の項目と対処方法を画面に示します。`aidlc engine plugin sync` のように Andon が実行できる対処には、ボタン（例：「プラグインの構成をそろえる」）を付けます。押すと実行して、Doctor をやり直します。そのほかの対処は、示された手順に沿って行ってください。日本語訳のない項目は「原文」で確認できます。

各ファイルの「原文」には、上流の `aidlc config` が返した説明と対処の原文を示します。「診断情報をコピー」は、ファイルごとの区分・案内・原文を JSON でコピーします。

## バックアップと失敗時の確認

反映前に、拡張機能の保存領域にバックアップを作成します。保存先は画面と実行ログに表示します。`manifest.json` に元のプロジェクト、変更したパス、元のファイルに対応する `.bin` ファイルを記録します。元のファイルが存在しなかった場合は `backup` が `null` です。

反映中にエラーが起きた場合は、変更済みの設定を戻します。ただし、別の処理による変更を検出したファイルは上書きせず、復元できなかった対象とバックアップの場所を表示します。診断と修正の間に元の設定が変わった場合や、AI に修正案を頼んだ後でファイルが変わった場合は、反映せずに止まります。アプリや OS が強制終了した場合も、バックアップを使って確認できます。`completed` ファイルがなければ、反映完了は確認できていません。実行中に表示される「中止」や画面を閉じる操作でも処理を中止できます。
