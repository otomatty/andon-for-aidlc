# 効果測定で案件を比較する

Dashboard のヘッダーから「効果測定」を開きます。現在の space にある案件を一覧にし、scope と depth で絞り込めます。VS Code / Cursor の拡張と、ブラウザ版 Dashboard で利用できます。

画面を開いたときに記録を読み取り、表示中の変更通知に合わせて再取得します。別の案件や別の端末から更新した記録を確認する場合は「更新」を押してください。ワークフローを実行したり、案件を選択したりしなくても一覧を確認できます。

## 表示する指標

| 指標           | 読み方                                                                                                                           |
| -------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| 完了までの時間 | ワークフローの開始から完了までの経過時間。休止や承認待ちも含みます。未完了案件の経過時間とは区別して表示します。                 |
| 承認待ち       | 承認待ち開始から承認・差し戻しまでの時間。終了した待ち時間と、現在待っている時間を分けます。並行する待ち時間は重複計上しません。 |
| 差し戻し       | 監査ログに記録された `GATE_REJECTED` の回数。通常は AI-DLC の承認ゲートでの Request Changes に対応します。                       |
| 品質チェック   | 検証できた成功、失敗、省略、未完了を分けます。ツール未導入や実行エラーを成功に数えません。                                       |

差し戻しには、ゲート中の成果物修正から復旧処理が補った `Recovered: true` の記録も含みます。そのため、Request Changes を明示的に選んだ回数と一致しない場合があります。GitHub の PR レビューでの Request changes や、AI レビュアーの NOT-READY 判定は、この回数に含めません。

「未記録」はゼロとは異なります。古い案件やフックが動いていなかった期間は、集計に必要な記録が揃わない場合があります。復旧時に補った承認待ち開始も、正確な時間の計測には利用しません。部分的に読み取れた案件は、その注意点を表示します。

監査イベントが10万件、監査ファイルが128個を超える場合や、監査ファイルの一部を読み取れない・解析できない場合は、その案件の監査ログに基づく指標を「未記録」にします。途中の記録だけで期間や回数を確定せず、理由を「記録の内訳」に表示します。

別端末の監査ファイルに同時刻の記録があり、その中に再開始・ジャンプ・承認などの境界が含まれる場合も、ファイル名から前後関係を推測せず監査指標を非表示にします。

この画面の時間は人の実作業時間ではありません。ホーム画面にある監査イベント間隔からの活動時間の推定とも別の指標です。

ホーム画面の時間の計算式と、休憩・持ち越しの扱いは[ステージ時間の算出方法](./stage-timing.md)で図解しています。

承認待ちの区間をすべて集計から除外した場合は、待ち時間を「未記録」とし、記録がある案件の件数にも含めません。除外区間数は「記録の内訳」に残します。終了した待機と待機中の時間は別々に扱い、開始と終了を対応付けられた0秒だけを確定した「0分」と表示します。

人の入力回数は、実行先のワークフローが明示された記録のみを数えます。現行の aidlc-workflows 2.11.1 の標準フックも `HUMAN_TURN` に実行先を記録しないため、通常実行と単独ステージ実行を区別できません。この形式の記録しかない場合、入力回数は「判別不可（実行先未記録）」となります。時刻やセッションの一致だけでは補完しません。正確な回数の収集には、エンジン側で呼び出し・質問への返答の実行先を記録する対応が必要です。

品質チェックは、その案件の監査ログに記録された検査の合計です。通常実行と単独ステージ実行の両方を含みます。現行の書き込み時センサーにも実行先情報がないため、主ワークフローだけの検査回数には分離しません。実行先タグの有無で集計対象を変えず、APIでは `sensors.scope = "intent-record"` として対象範囲を示します。

## 比較するときの条件

scope、depth、案件の規模や難易度が近いものを比較してください。品質チェックの成功率だけで品質全体を判断せず、対象件数、省略された検証、リリース後の不具合も確認します。

AI-DLC の導入による短縮率を出すには、不使用時や導入前の比較データが必要です。この画面は既存の実行記録を集計するもので、削減時間や改善率を自動的に推定するものではありません。

## 読み取り範囲

効果測定は、対象リポジトリ内の `aidlc/` に保存された実行記録を読み取り、ローカルで集計します。状態や監査ログを書き換えず、会話本文や回答内容を集計APIへ返しません。クラウドサービスやデータベースは追加しません。

以下のパスは対象リポジトリのルートからの相対パスです。`<record>` は案件ごとのディレクトリ名を表します。

| 読み取るファイル                                       | 用途・表示する項目                                                                           |
| ------------------------------------------------------ | -------------------------------------------------------------------------------------------- |
| `aidlc/active-space`                                   | 集計対象の space。ファイルがない場合は `default`。                                           |
| `aidlc/spaces/<space>/intents/intents.json`            | 案件の識別情報と、状態が読み取れない場合の補助情報。                                         |
| `aidlc/spaces/<space>/intents/<record>/aidlc-state.md` | 案件名、scope、depth、状態。対応する State Version の記録を集計。                            |
| `aidlc/spaces/<space>/intents/<record>/audit/*.md`     | 開始・完了、承認待ち、差し戻し、品質チェック。「記録の内訳」には人の入力・修正の回数も表示。 |

案件の状態・監査ログは Git で共有する記録です。記録のない項目をデモ値で補うことはありません。

API は互換性のためレビュー・利用量の集計項目を保持し、`aidlc/.aidlc-sessions/usage-ledger.json` があれば利用量を照合します。画面にはレビュー初回合格率、トークン数、推定費用を表示しません。

拡張とブラウザは共通の `GET /api/effectiveness` を使用します。初期のワークフロー表示とは独立して取得するため、案件横断の集計がホーム画面の初回表示を待たせません。

## 別のリポジトリの記録をブラウザで確認する

Dashboard を Andon 側でビルドしてから、記録を読みたいリポジトリへ移動してサーバーを起動します。PowerShell の例です。2つのパスを手元のチェックアウトに置き換えてください。

```powershell
$guideRepo = "C:\src\andon-for-aidlc"
Set-Location $guideRepo
bun install
bun run build:dashboard

Set-Location "C:\src\your-project"
bun "$guideRepo/packages/dashboard-server/src/cli.ts" --port 4700
```

[ローカルの Dashboard](http://127.0.0.1:4700) を開き、ヘッダーの「効果測定」を選びます。サーバーを起動した作業ディレクトリが参照対象です。`aidlc/` 自体や案件ディレクトリではなく、その親のリポジトリルートから起動してください。対象に案件の記録がなければ「計測対象の案件がありません」と表示します。

画面のコードを変更した場合は、Andon 側で `bun run build:dashboard` を再実行してブラウザを更新します。サーバーは `Ctrl+C` で停止できます。
