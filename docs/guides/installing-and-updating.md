# CLI とエンジンを導入・更新する

> 対象: AIDLC Guide から AI-DLC を導入・更新する開発者  
> 関連: [更新時の問題を診断・修正する](./updating-workflows.md) · [バージョン確認の設計](../maintenance/version-gate-design.md)

AIDLC Guide は、拡張で検証した対応版の aidlc-workflows を導入・更新します。対応版は `packages/shared-types/src/workflows-management.ts` の `WORKFLOWS_TARGET_VERSION` で決まります。上流の最新版へ自動では追従しません。

## 初回のセットアップ

コマンドパレットから `AIDLC Guide: Setup` を実行します。画面には 3 つのステップが並び、いま進めるステップだけが開いています。開いているステップのボタンを押して進めます。

| ステップ             | 画面の操作             | 内容                                                                                                                                                    |
| -------------------- | ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1 このマシンの CLI   | 「CLI をインストール」 | このマシンの `aidlc` を準備します。固定バージョンが対応版より古いプロジェクトでは「CLI を更新」になり、確認してから進めます。固定バージョンは変えません |
| 2 プロジェクトの設定 | 「プロジェクトを設定」 | 新規プロジェクトでは使うツールを選びます。既存プロジェクトではリポジトリにある設定を使うので、最初から済みになります                                    |
| 3 完了               | 「セットアップを完了」 | Dashboard へ進みます。インテントの作成前でも完了できます。「診断を実行（任意）」で `aidlc doctor` の結果も確かめられます                                |

終わったステップは 1 行にたたまれます。押すと、使っているバージョンなどの詳細が開きます。画面に戻ったときと各操作のあとに、フォルダーの状態を読み直します。

この画面だけでは進められないときは、理由を 1 文で示し、「更新・修復画面を開く」を主ボタンにします。たとえば、拡張から入れられない版の CLI が必要なときや、リポジトリ内のバージョンがそろっていないときです。Codex を使うフォルダーが Git リポジトリでないときは、`git init` のあと「もう一度確認」を押します。ワークスペースを信頼していないときは、「ワークスペースを信頼」から始めます。

既存のプロジェクトに参加するときは、共有のエンジンを更新しなくてもセットアップを完了できます。プロジェクトの固定バージョンが対応版と違う場合は、セットアップ後に表示される更新の案内に従って揃えてください。

### CLI の確認

- 新しい統合ターミナルには PATH を反映します。「このマシンの CLI」のステップを開き、「新しいターミナルで CLI を確認」で動作を確かめられます。
- Windows の Git Bash では `aidlc.cmd --version`、コマンド プロンプトと PowerShell では `aidlc --version` で確認します。
- 外部のターミナルの PATH は、公式の手順に沿って設定してください。

### ツールを追加する

- 設定済みのプロジェクトでは、「完了」のステップの「ツールを追加」で選択欄が開きます。Dashboard の設定の「ツール追加を開く」と `AIDLC Guide: Install Workflows` も、同じ画面をこの状態で開きます。
- 先にプロジェクトの更新が必要なときは、選択欄の代わりに「更新・修復画面を開く」を表示します。

### 完了したあと

- 完了状態はフォルダーごとに記録します。完了後に CLI や設定の問題が見つかっても、セットアップは自動で表示しません。
- `AIDLC Guide: Open` は、完了前でプロジェクトの設定が済んでいないときだけセットアップを開き、それ以外は Dashboard を開きます。拡張を起動しただけでは、セットアップ画面を開きません。
- 完了後にセットアップを開き直すと、「セットアップは完了しています」と「ダッシュボードを開く」を表示します。
- 信頼済みのフォルダーでは、登録済みの文書参照連携を起動時に更新します。対象は、拡張の更新で変わる MCP の参照先と、拡張が管理する Skill です。文書参照の登録の有無は、セットアップを自動で開くかどうかには影響しません。

## 更新画面

右上のメニューの「設定」→「更新・修復」→「更新画面を開く」で開きます。コマンドパレットの `AIDLC Guide: Update Workflows` でも開けます。

| 対象                   | 内容                                                                 |
| ---------------------- | -------------------------------------------------------------------- |
| このマシンの CLI       | 対応版に更新します（確認ダイアログあり）。共有ファイルは変更しません |
| プロジェクトのエンジン | 準備済みの実行環境で、全ツールと固定バージョンを対応版に揃えます     |
| 拡張機能               | 「拡張機能の更新を確認」で、AIDLC Guide の新しい版を確認します       |

- インストールでは複数のツールを選べます。更新では、プロジェクトに設定済みの全ツールを同じ版に揃えます。
- 公式コマンドで生成した設定からツールごとのファイルを取り込み、既存の共通設定と成果物は保持します。
- 古い設定へのツール追加は、全体の更新が終わってから行います。新しい設定からのダウングレードはしません。
- 進行中のワークフローがあってもツールの追加・更新はでき、作業はそのまま続けられます。
- アクティブな Space とプラグインの選択も引き継ぎます。構成済みのプラグインは元のパッケージを検証して同じ構成を再生成し、確認できない場合は既存の設定を保持して止まります。
- Windows で VS Code を管理者として実行している場合は、導入の前に公式インストーラーと同じ警告を出して確認します。

## この PC の CLI だけが新しいとき

未導入の版を自動で取得できるのは対応版だけです。マシンの既定の CLI が対応版より新しくても、更新画面から対応版を追加で導入でき、処理後も新しい既定の版を維持します。

プロジェクトがバージョンを固定していない場合は、更新画面で次のどちらかを選びます。

| 選択肢                                 | 影響                                                                    |
| -------------------------------------- | ----------------------------------------------------------------------- |
| 「このプロジェクトを（対応版）に固定」 | `.aidlc-version` を作ります。リポジトリで共有するのでコミットが必要です |
| 「この PC の既定を（対応版）に戻す」   | 固定していないほかのプロジェクトにも影響します                          |

プロジェクトの固定バージョンが対応版でない間は、バージョン確認によって Guide の主な機能を使えません。

## 結果の確認と失敗したとき

- 更新後は、全ツールの版・プロジェクトの固定バージョン・最後の診断を確認します。
- 失敗した場合は、適用の状況・復元の結果・次の操作を表示します。
- 設定の反映後に診断だけが失敗した場合は、「Doctor を再実行」で確かめられます。
- セットアップとツール追加では、一部のツールが失敗しても完了したツールは保持します。失敗したツールだけを再試行するか、選択から外して先に進めます。
- 更新では、設定済みの全ツールを毎回まとめて処理します。
- 診断では設定済みの各ツールを検査し、ツール名付きで結果を表示します。
- 設定の競合で更新できない場合は、[更新時の問題を診断・修正する](./updating-workflows.md)を参照してください。

## 同時に扱えないもの

- 設定フォルダーが競合する GitHub Copilot と opencode、Kiro CLI と Kiro IDE は、それぞれ同時に設定できません。
- 同じ拡張ホストで複数のフォルダーを開いていても、インストール・更新は一度に 1 件だけです。PC の既定の版を戻して処理が終わるまで、ほかのフォルダーでの実行は待ってから再試行してください。
